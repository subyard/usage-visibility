04 / from observation to action

Spot the pattern.
Explain the cause.

SignalEvidence to checkPossible change

Waiting with an expensive model

Repeated wait-invoking responses, agent role, context size and cached input.

Use completion events. Do independent work while tests run.

A test already passed

The same check, code and environment, with a previous passing result.

Reuse the result when the relevant inputs have not changed.

Too much observation

Polling and update frequency, new information between calls, time to delivery.

Increase the interval. Report state changes and completion.

A signal starts a review. A rerun after a code change, failure or flaky test may be justified.

01. Scale and the largest connected family

Tokens across 179 sessions
Wait-associated tokens
Largest family, 20 sessions

The lead and 19 selected descendants used tokens; (%) belong to wait-invoking responses. Only aggregate metrics are published; session identifiers and source locations remain in the local audit.

Sum token_usage_record.payload.usage by unique thread and response_id. Wait numerator: responses whose tool calls are exclusively wait_agent, sleep or wait. Denominator: all responses in the same scope and time slice. Count input + output; cached input and reasoning output are included subsets.

wait continues a yielded tool execution. It is distinct from waiting for a child via wait_agent or sleeping. The model response invokes the wait; the blocked time itself does not generate model tokens. These totals do not establish avoidable cost.

These are disjoint response categories: 1,051 wait continuations; 162 responses invoking one direct write_stdin poll with empty input and a literal process ID, without loops or callbacks; and 345 send_message replies (343 to the lead, two to a peer). Mixed execution bodies are excluded from the direct-poll category.

Responses can include useful analysis, and messages can carry findings. The share is an attribution signal, not proof that all observation is waste. CPU use, dollar cost, task success and potential savings were not measured. Repeated tests still require comparison of code, environment and results.
