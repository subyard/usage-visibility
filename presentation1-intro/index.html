04 / from observation to action

Spot the pattern.
Explain the cause.

SignalEvidence to checkPossible change

Waiting with an expensive model

Repeated wait-invoking responses, agent role, context size and cached input.

Use completion events. Do independent work while tests run.

A test already passed

The same check, code and environment, with a previous passing result.

Reuse the result when the relevant inputs have not changed.

Too much observation

Polling and update frequency, new information between calls, time to delivery.

Increase the interval. Report state changes and completion.

A signal starts a review. A rerun after a code change, failure or flaky test may be justified.

05 / metrics with clear meaning

One step.
Several dimensions.

T

Tokens

Input, cached input and output separately. Model, agent role and specific step.

$

Cost

Model pricing on the request date. Keep estimates separate from actual billing.

↻

Compute

CPU, memory and test processes. Process elapsed time separately from CPU time.

→

Delivery

Time to outcome, waits and blockers. Task success and the checks that confirm it.

Task→Agent→Model step / tool→Usage + outcome

Cached tokens are part of input. Reasoning tokens are part of output. Avoid double counting and keep tokens separate from dollars.

Session snapshot for October 5–6, 2026, UTC. These are two related Codex logs from Yard: a case study, not statistics for all tasks.

01. Lead-agent waiting

Session , model . The test observer is child session , model .

Sum token_usage_record.payload.usage by unique response_id. Numerator: responses whose tool calls are exclusively wait_agent or sleep. Denominator: all lead-agent responses in the period. Count input + output; do not add cached input or reasoning output a second time.

Wait-associated tokens
All lead-agent tokens
Cached input in wait responses

Wait-invoking responses may include reasoning. Waits relate to several agents. The share associates model responses with tool calls; it does not establish that all these tokens could be saved.

During the test observer's lifetime (Oct 5, 20:02–Oct 6, 11:37 UTC), the lead spent about 5 hours 17 minutes in 466 wait_agent calls, or 33.9% of that interval. The sleep call is excluded from this duration. This is a time share, not a token share. The tool does not identify which agent was being awaited.

02. Test observation and reruns

In full_tests_luna, count send_message calls and tools.write_stdin calls inside execution. Count test launches only from literal cmd arguments to tools.exec_command, excluding quoted mentions and file reads.

Run counts do not establish waste. Code versions, environment and results must be compared before calling a run redundant. CPU use, dollar cost and potential savings were not measured in this snapshot.
