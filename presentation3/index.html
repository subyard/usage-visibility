The last token column before the dollar amount is treated as total tokens: each value equals the sum of the three nonzero preceding token columns. Column headers are outside the screenshot, so no input, output or cache breakdown is assigned.

Total: 13,396,361,355 tokens (13.4B). Daily average: 13,396,361,355 ÷ 8 = 1,674,545,169.375 tokens (1.67B). The original screenshot also shows October 5; that date is excluded from these calculations. Total tokens measure volume; they do not establish cost or efficiency.

Harnesses: local records and optional collection

Slide 3 compares Codex, Claude Code and OpenCode. Its rows are our collection categories, not a shared vendor hierarchy: traces are telemetry, alongside metrics and events. Inclusion of OpenCode restores the comparison; D13's implementation priorities remain unchanged pending clarification. Sources checked October 14, 2026; no user configuration or private session files were inspected.

Codex: local history, saved thread items and usage events, and telemetry. The repository's existing scripts/collect_evidence.py reads rollout timestamps, tool calls/results and token usage; this is a version-dependent local format, not a stable export API. Exporter settings separate logs, metrics and traces. Token categories include input, cached input, output and reasoning output; cached and reasoning counts are subsets, not extra tokens. User-prompt log content is opt-in. OpenAI usage/health analytics are separate from custom log/trace export; metrics default to Statsig, and analytics.enabled=false also disables custom OTLP metrics in the CLI.

Claude Code: local application data documents JSONL transcripts, prompt history and aggregate token/cost statistics. The transcript schema is internal; default session cleanup is 30 days. Native beta spans require CLAUDE_CODE_ENABLE_TELEMETRY=1, CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1 and trace exporter configuration. API/tool spans carry elapsed timings; token categories include input, output, cache read and cache creation. Prompt/tool content export has separate opt-in controls, which do not redact local transcripts. Provider operational telemetry is separate from export to our collector.

OpenCode: the storage documentation identifies local session/message data under ~/.local/share/opencode/ on Linux/macOS. The CLI exports a session as JSON; opencode stats summarizes tokens and cost. The SDK and plugin hooks provide events for a custom collection adapter. This is not equivalent to a built-in OTLP metrics/log exporter. Development-source fields are version-dependent; they do not establish capabilities of the installed version.

OpenCode source is pinned to 34d8ded0c58dd66808c1d60e081e8c66da12a896: the session persistence schema records token/cache/reasoning counts, cost and timestamps; the message schema includes assistant usage and tool input/output, status and timings. These are development schemas, not a guaranteed stable storage contract. The reviewed experimental config and LLM runner do not expose the older experimental.openTelemetry option. Native trace export is therefore marked unverified, not universally absent. An SDK/plugin tracing adapter is a proposed integration path, not a tested exporter.

The process-resource gap is our assessment of the documented telemetry catalogs: tool wall-clock duration does not measure child-process CPU or RAM. OS/process instrumentation and cross-harness task/agent/step correlation still require implementation and real-run validation. Existing candidate ratings are unchanged.
